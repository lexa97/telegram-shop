# Интеграционные сценарии (mock Telegram)

Здесь — **человекочитаемые сценарии** end-to-end логики бота. Код живёт в `tests/integration/`.

**Стек:** in-memory SQLite (как в `tests/conftest.py`), мок Bot API, вызов хендлеров или цепочка callback/message.

## Статусы

| Статус | Значение |
|--------|----------|
| `draft` | Идея, приложение ещё не готово |
| `ready` | Можно переносить в pytest |
| `done` | Есть тест, ссылка в колонке «Код» |
| `skip` | Не в v1 / отложено (кратко почему) |

### INT-001 — Старт, корзина, пополнение, оплата

**Статус:** done  
**Роли:** новый пользователь  
**Предусловия:** каталог с тремя позициями в одной категории: два finite-ключа и один unlimited (infinity) STOCK; баланс 0.

**Шаги**

1. `/start` — регистрация.
2. Магазин → категория → три разных товара (finite / finite / infinity) → «в корзину» каждый.
3. Экран корзины — сумма 150 ₽ (60+40+50).
4. Профиль → пополнение → сумма 200 ₽ → CryptoPay (mock) → «проверить оплату».
5. Оформление корзины → подтверждение.

**Ожидаемый результат**

- Баланс после пополнения 200 ₽, после покупки 50 ₽.
- Корзина пуста, 3 записи в покупках.
- Чек (`cart.checkout_receipt` в тестах с моком `localize`).

**Код**

- `tests/integration/test_int_001_shop_cart_topup_checkout.py::test_full_purchase_flow`
