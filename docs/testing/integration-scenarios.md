# Интеграционные сценарии (mock Telegram)

Здесь — **человекочитаемые сценарии** end-to-end логики бота. Код живёт в `tests/integration/`.

**Стек:** in-memory SQLite (как в `tests/conftest.py`), мок Bot API, вызов хендлеров или цепочка callback/message.

## Статусы

| Статус | Значение |
|--------|----------|
| `draft` | Идея, приложение ещё не готово |
| `ready` | Можно переносить в pytest |
| `done` | Есть тест, ссылка в колонке «Код» |
| `skip` | Не в v1 / отложено (кратко почему) |

## Реестр

Добавляйте строки **сверху** (новые ID — по порядку `INT-001`, `INT-002`, …).

| ID | Название | Статус | Код | Примечание |
|----|----------|--------|-----|------------|
| — | *пример: регистрация и первый заход в магазин* | `draft` | — | удалите или замените, когда появятся реальные сценарии |

## Шаблон сценария (копируйте блок под реестром)

### INT-XXX — Краткое название

**Статус:** draft | ready | done | skip  
**Роли:** пользователь / админ / owner  
**Предусловия:** что уже в БД или env (баланс, товар, роль).

**Шаги**

1. …
2. …

**Ожидаемый результат**

- БД: …
- Ответ бота (ключ localize / фрагмент текста / callback data): …

**Код (когда done)**

- `tests/integration/test_int_xxx_....py::test_...`
