# ТЗ-01 — Денежные единицы: копейки и атомарный баланс

**Исполнитель:** субагент «данные / миграции».  
**Исходное ТЗ:** §7, §16, §19.  
**Зависимости:** нет (первый слой).  
**Блокирует:** все остальные финансовые задачи.

## Цель

Все деньги в БД, API и транзакциях — целые копейки (`BIGINT`). 299 ₽ = `29900`. Никаких `float`/`double`/`Numeric` для сумм.

## Контекст кода

Сейчас суммы — `Decimal`/`Numeric(12,2)`:

- `User.balance`, `Goods.price`, `BoughtGoods.price`, `Operations.operation_value`, `Payments.amount`, `ReferralEarnings.amount`, `PromoCodes.discount_value` (для `fixed`/`balance`).
- Покупка: `bot/database/methods/transactions.py` (`buy_item_transaction`, `process_payment_with_referral`).
- Цены: `bot/database/methods/pricing.py` (`quantize("0.01")`).
- UI часто делает `int(amount)` как рубли.

Паттерн блокировок баланса уже есть: `select(User).with_for_update()`. Его сохранить.

## Задача

1. Ввести единый тип/хелперы: `rub_to_cents`, `cents_to_display` (только для UI).
2. Alembic-миграция: существующие `Numeric` денежные колонки → `BIGINT` копеек (`value * 100`), с проверкой что дробных тысячных нет.
3. Обновить модели, CRUD, транзакции, pricing, handlers, i18n-форматирование, тесты, factories.
4. `CHECK (balance >= 0)` (или эквивалент) на пользователя.
5. Промо `percent` остаётся процентом (не деньги); `fixed` и `balance` — в копейках.
6. Документировать в комментарии модуля: «все money int = копейки».

## Направление

- Не вводить `Money` ORM-тип, если это раздует SQLAlchemy; достаточно `mapped_column(BigInteger)` + функции.
- Не менять бизнес-правила покупки в этом ТЗ — только единицы и инварианты баланса.
- Корзина `_split_amount` уже считает cents через `* 100` — упростить до целочисленного деления копеек.

## Вне скоупа

Platega, заказы, провайдеры, смена реферала.

## Критерии приёмки

- [ ] В моделях нет `Numeric`/`Float` на денежных полях; тип колонок `BIGINT`.
- [ ] Миграция обратима или имеет явный downgrade; на тестовых данных 10.50 → 1050.
- [ ] Пополнение + покупка + реф.начисление в существующих тестах переведены на копейки и зелёные.
- [ ] Гонка двух списаний не уводит баланс < 0 (тест с двумя конкурентными транзакциями / retry как в текущем `buy_item_transaction`).
- [ ] Двойное зачисление по тому же `Payments (provider, external_id)` по-прежнему невозможно.
- [ ] UI показывает рубли (299), в БД 29900 — выборочная проверка handlers.
- [ ] `docs/MEMORY.md`: решение «копейки везде».
