# ТЗ-07 — Промокоды и реферальная система

**Исполнитель:** субагент «loyalty».  
**Исходное ТЗ:** §11, §12.  
**Зависимости:** ТЗ-01, ТЗ-02; интеграция в checkout ТЗ-06.  
**Блокирует:** корректная прибыль заказа, часть админки.

## Цель

Промо: percent / fixed / bonus на баланс; срок, max uses, лимит на пользователя, min сумма, scope товар/категория. Использование атомарно.

Реферал: персональная ссылка (уже есть). Вознаграждение **один раз на заказ** при выполнении условия покупки, отдельно от баланса операции заказа, snapshot в заказе.

## Контекст кода

Промо уже близко к ТЗ: `PromoCodes`, `PromoCodeUsages` unique `(promo_id, user_id)` — это **лимит 1 на пользователя навсегда**. ТЗ: «лимит на пользователя» — обобщить: поле `max_uses_per_user` (default 1 = как сейчас).

Нет `min_order_cents`.

Реферал сейчас в `process_payment_with_referral` при **пополнении**. Нужно:

- убрать начисление с top-up;
- начислять при `Order.COMPLETED`;
- unique `(order_id)` на `ReferralEarnings`.

Ссылка и UI статистики: `bot/handlers/user/referral_system.py` — поправить тексты «с покупок».

## Задача

1. Поля промо: `min_order_cents`, `max_uses_per_user`; usage не только unique user если max>1 — тогда unique `(promo_id, user_id, order_id)` + счётчик.
2. Атомарный increment `current_uses` в той же транзакции, что заказ (как сейчас `with_for_update` на промо).
3. Balance-промо: зачисление копеек, без смешивания с заказом товара (текущий redeem flow сохранить, в копейках).
4. Реферал: таблица/поля `order_id` unique; `amount_cents` от `order.total` и процента (env или настройка БД — если БД, ключ в settings; не обязательно админка в этом ТЗ).
5. Начисление на `User.balance` реферера + запись `ReferralEarnings` + `order.referral_amount_cents` в snapshot.
6. Условие: только COMPLETED; не на REFUNDED (если refund после начисления — вычесть/сторно реферала; описать правило: **сторно реферала при refund заказа**).
7. Переписать тесты `tests/test_promo_*.py`, `tests/test_referral_system.py`.

## Направление

- Не делать многоуровневую сеть.
- Процент реферала: сохранить `EnvKeys.REFERRAL_PERCENT` если админ-настройка БД не готова; заложить чтение из settings table optional.

## Вне скоупа

Новые типы промо, кэшбек внешний.

## Критерии приёмки

- [ ] Промо просрочен / max_uses / чужой товар — отказ, заказ не создаётся либо без скидки строго по текущим правилам ошибки.
- [ ] Два параллельных redeem одного last-use промо: один успех (тест гонки).
- [ ] `min_order_cents` не даёт скидку ниже порога.
- [ ] `max_uses_per_user=2` позволяет две покупки, третья нет.
- [ ] Top-up **не** создаёт ReferralEarnings.
- [ ] Два COMPLETED заказа реферала → две записи; повтор обработки одного заказа → одна запись.
- [ ] Refund заказа сторнирует реферальную выплату (баланс реферера и запись).
- [ ] Прибыль заказа учитывает `referral_amount`.
