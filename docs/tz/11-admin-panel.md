# ТЗ-10 — Административная web-панель

**Исполнитель:** субагент «SQLAdmin».  
**Исходное ТЗ:** §13.  
**Зависимости:** модели из ТЗ-02…09, роли ТЗ-08.  
**Блокирует:** удобство эксплуатации; не блокирует ядро checkout если модели уже есть.

## Цель

Web-панель (`bot/web/admin.py`, SQLAdmin) даёт управление всем списком из §13. Для API-товаров — форма связи с поставщиком. Для склада — массовая загрузка (сервис из ТЗ-03).

## Контекст кода

Уже есть views: User, Role, Category, Goods, ItemValues, BoughtGoods, Payments, Promo, Referral, Audit, Operations, Reviews и т.д. (`AuditModelView`). Экспорт CSV `bot/web/export.py`. Логин, rate limit.

Нет: Order, Provider, GoodsProviderLink, PaymentInstrument/Gateway, Tickets, массовый import UI, прибыль в статистике заказов.

## Задача

Зарегистрировать ModelView / кастомные страницы:

- пользователи и правка баланса (уже есть — перевести на копейки отображение);
- товары/категории + fulfillment_type, allows_gift;
- склад + форма paste/upload ключей;
- API-поставщики и связи (external id, cost_cents, params JSON, retail на Goods);
- заказы: статусы read-mostly, кнопка ручного refund (сервис ТЗ-02/06);
- платежи;
- промо, рефералы;
- тикеты: статус + ответ (вызов сервиса ТЗ-09);
- статистика: продажи, прибыль по snapshot заказов (не «текущая цена товара»);
- роли;
- аудит;
- платёжные инструменты и шлюзы (секреты не светить в списке — masked).

Права SQLAdmin согласовать с битами ТЗ-08 (сейчас доступ в админку шире/уже — проверить `AdminAuth`).

## Направление

- Не писать отдельный SPA.
- Опасные действия через существующий audit mixin.
- JSON-поля поставщика — textarea, валидация JSON.

## Вне скоупа

Редизайн UI, новые графики JS сверх простого list/filter.

## Критерии приёмки

- [ ] Каждый пункт §13 имеет экран или явно наследуется существующим view (чеклист в MEMORY).
- [ ] Создание GoodsProviderLink без кода.
- [ ] Импорт склада из админки вызывает сервис ТЗ-03, виден отчёт.
- [ ] Ручной refund с панели меняет заказ и баланс, пишет audit.
- [ ] OPERATOR не видит/не сохраняет секреты шлюза.
- [ ] Статистика прибыли берёт `order.profit_cents` COMPLETED.
- [ ] Админка стартует на `/admin` как в README.
