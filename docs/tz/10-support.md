# ТЗ-09 — Поддержка пользователей (тикеты)

**Исполнитель:** субагент «support».  
**Исходное ТЗ:** §15.  
**Зависимости:** пользователи есть; заказы ТЗ-02 желательны для «связанные заказы».  
**Блокирует:** UX бота ТЗ-11, админка тикетов ТЗ-10.

## Цель

Пользователь создаёт обращение **в боте**. Оператор смотрит, отвечает, меняет статус, видит связанные заказы. История переписки хранится.

## Контекст кода

Кнопка «Поддержка» — `tg://user?id=helper` (`bot/keyboards/inline.py`). Тикетов нет.

## Задача

1. Модели: `SupportTicket` (user_id, status `open|pending|closed`, linked_order_id nullable, created/updated), `SupportMessage` (ticket_id, author_role `user|staff`, body, created_at).
2. Пользователь: создать тикет (текст), писать в открытый, закрыть со своей стороны опционально.
3. Антиспам: один активный тикет или лимит; rate limit middleware уже есть — не дублировать тяжело.
4. Оператор: список, ответ → Telegram-сообщение пользователю + запись в history.
5. Связь с заказом: пользователь может указать ID заказа / «из карточки заказа открыть тикет».
6. Не использовать сырой chat с helper как единственный канал после внедрения.

## Направление

- Handlers: `bot/handlers/user/support.py`, admin `bot/handlers/admin/support.py` или только web в ТЗ-10. **Минимум:** бот для пользователя + либо web либо in-chat для оператора. Предпочтение: бот user + SQLAdmin staff (ТЗ-10) + in-chat список если время.
- Медиа в v1 можно не принимать (только текст) — зафиксировать в MEMORY если так.

## Вне скоупа

SLA, внешний Helpdesk, IMAP.

## Критерии приёмки

- [ ] Пользователь создаёт тикет, видит историю.
- [ ] Ответ оператора доходит в Telegram и сохраняется в `SupportMessage`.
- [ ] Смена статуса open↔closed работает и недоступна чужому пользователю.
- [ ] Тикет с `order_id` показывает заказ в выдаче оператору (API/админ).
- [ ] Пользователь A не видит тикет B.
- [ ] Тесты handlers/моделей без живого Telegram API (как остальные tests).
