# Ручная приёмка (короткий чеклист)

Автотесты закрывают §20 (см. [14-tests-launch.md](14-tests-launch.md)). Перед продом пройдите этот список на staging с реальным ботом.

## Подготовка

- [ ] `cp .env.example .env`, заданы `TOKEN`, `OWNER_ID`, `POSTGRES_*`, сильные `SECRET_KEY` / `ADMIN_PASSWORD`
- [ ] `docker compose up -d --build` или локально: `alembic upgrade head` + `python run.py`
- [ ] `/health` на панели: `http://localhost:9090/health` → `healthy`
- [ ] Platega (если включена): в кабинете Platega webhook `https://<домен>/webhooks/platega`, заголовки `X-MerchantId` / `X-Secret` как в `PaymentGateway`

## Сценарии

1. [ ] **/start** — новый пользователь, меню; реферальная ссылка `?start=ref_<id>` привязывает реферера
2. [ ] **Пополнение** — Platega (или другой включённый инструмент), баланс вырос на сумму в **рублях** (в БД — копейки)
3. [ ] **Повтор webhook Platega** — повторная доставка того же `id` не удваивает баланс
4. [ ] **Покупка STOCK** — ключ в чате, баланс уменьшен
5. [ ] **Два пользователя, один ключ** — второй получает «нет в наличии»
6. [ ] **API-товар** — после оплаты статус «обрабатывается», затем ключ (воркер / фон)
7. [ ] **Промокод** — скидка в чекауте, лимит использований соблюдается
8. [ ] **Реферал** — начисление после **покупки**, не после пополнения
9. [ ] **История заказов** — статусы без утечки ключа до `COMPLETED`
10. [ ] **Тикет поддержки** — создать, ответ оператора (бот или web)
11. [ ] **Роли** — OPERATOR: пользователи/заказы/тикеты, без смены ролей и без прямого изменения баланса
12. [ ] **Refund в админке** — заказ → REFUNDED, запись в audit
13. [ ] **Вывод средств** — в v1 **нет** (ожидаемо отсутствует)

## После деплоя

- [ ] Логи без сырых ключей товаров в INFO
- [ ] Telegram webhook (если `WEBHOOK_ENABLED=1`): прокси только на `WEBHOOK_PORT`, панель не светить в интернет без TLS
